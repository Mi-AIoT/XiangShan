## 2. XiangShan 上的运行环境

### 2.1 运行环境：存疑

**SPEC2006 在 XiangShan 上的运行环境（裸机 vs Linux）需要进一步确认。**

**已知事实**：
1. XiangShan **能运行 Linux**（`ready-to-run/linux.bin` 存在）
2. SPEC2006 **标准版本需要 OS**（使用 libc、文件 I/O 等）
3. Checkpoint **由 NEMU 生成**（NEMU 是 ISA 模拟器，支持裸机和 Linux）
4. SPEC2006 的编译脚本**在 NFS 上**（`/nfs/home/share/ci-workloads/env-scripts/`），不在代码仓库中

**两种可能的运行方式**：

```
可能方式 1：裸机运行
┌─────────────────────────────────────────────────────────────────────────────┐
│  XiangShan CPU                                                              │
│  └── SPEC2006 程序（裸机二进制，静态链接，无 OS）                           │
│      - 无 pthread 库                                                        │
│      - 无 OpenMP 运行时                                                     │
│      - 多线程 benchmark 被编译为单线程模式                                  │
└─────────────────────────────────────────────────────────────────────────────┘

可能方式 2：Linux 运行
┌─────────────────────────────────────────────────────────────────────────────┐
│  XiangShan CPU                                                              │
│  └── Linux 内核                                                             │
│      └── SPEC2006 程序（用户态，动态/静态链接）                            │
│          - pthread 库可用                                                   │
│          - OpenMP 运行时可用                                                │
│          - 多线程 benchmark 正常运行                                        │
```

### 2.3 如果是裸机运行

**裸机程序的特征**：

```c
// 典型的裸机程序结构
int main() {
    // 1. 初始化（无 OS 支持）
    //    - 设置栈指针（由启动代码完成）
    //    - 初始化全局变量
    
    // 2. 运行 benchmark
    for (int i = 0; i < iterations; i++) {
        benchmark_function();
    }
    
    // 3. 终止
    ecall();  // 触发 trap，仿真器检测到 GOOD TRAP
    return 0;
}
```

**裸机环境下多线程 benchmark 的处理**：
- 无 pthread 库 → 无法创建线程
- 无 OpenMP 运行时 → 无法并行执行
- 多线程 benchmark 被编译为单线程模式

### 2.4 如果是 Linux 运行

**Linux 运行的特征**：
- 完整的操作系统支持
- pthread 库可用
- OpenMP 运行时可用
- 多线程 benchmark 正常运行
- **需要定时器中断**（用于任务调度）

### 2.5 两种方式的对比

## 3. 任务调度分析

### 3.1 任务调度的前提

**任务调度需要以下条件**：

```
1. 多个任务（进程/线程）
2. 操作系统内核
3. 定时器中断（用于时间片轮转）
4. 上下文切换机制
5. 调度算法（CFS、RR 等）
```

### 3.2 如果是裸机运行

**裸机环境下，SPEC2006 不需要任务调度**：

```
1. 只有一个任务（单线程程序）
2. 没有操作系统
3. 不需要定时器中断
4. 不需要上下文切换
5. 不需要调度算法
```

**单线程程序的执行模型**：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    单线程程序执行模型（裸机）                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  程序启动                                                                   │
│      │                                                                      │
│      ▼                                                                      │
│  ┌──────────────┐                                                          │
│  │ 初始化       │  设置栈指针，初始化全局变量                              │
│  └──────────────┘                                                          │
│      │                                                                      │
│      ▼                                                                      │
│  ┌──────────────┐                                                          │
│  │ main()       │  程序入口                                                │
│  └──────────────┘                                                          │
│      │                                                                      │
│      ▼                                                                      │
│  ┌──────────────┐                                                          │
│  │ 循环执行     │  for (i = 0; i < N; i++) { benchmark(); }               │
│  └──────────────┘                                                          │
│      │                                                                      │
│      ▼                                                                      │
│  ┌──────────────┐                                                          │
│  │ ecall        │  触发 trap，程序终止                                     │
│  └──────────────┘                                                          │
│                                                                             │
│  特点：                                                                     │
│  - 单一执行流                                                               │
│  - 无阻塞操作                                                               │
│  - 无 I/O 等待                                                              │

│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 如果是 Linux 运行

**Linux 环境下，SPEC2006 需要任务调度**：

```
需要的组件：
1. pthread 库         → 提供线程创建、同步原语
2. 操作系统内核       → 管理线程、调度
3. 定时器中断         → 时间片轮转调度
4. 上下文切换         → 保存/恢复线程状态
5. 同步原语           → mutex、semaphore、condition variable
```

## 4. Checkpoint 与单线程

### 4.1 Checkpoint 的工作原理

**Checkpoint 保存单线程程序的状态**：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Checkpoint 保存内容                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  CPU 状态：                                                                  │
│  - 32 个通用寄存器 (x0-x31)                                                │
│  - 32 个浮点寄存器 (f0-f31)                                                │
│  - PC（程序计数器）                                                         │
│  - CSR（mstatus, mepc, mcause, ...）                                       │
│                                                                             │
│  内存状态：                                                                  │
│  - 物理内存快照（几 GB）                                                   │
│                                                                             │
│  不保存：                                                                    │
│  - 线程状态（因为没有线程）                                                │
│  - 调度队列（因为没有调度器）                                              │
│  - 中断状态（因为中断禁用）                                                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 恢复后的执行

**从 checkpoint 恢复后**：

```
1. 恢复 CPU 状态（寄存器 + CSR）
2. 恢复内存状态
3. 从 checkpoint 的 PC 继续执行
4. 程序继续运行，直到 ecall 终止

整个过程：
- 只有一个执行流
- 没有线程切换
- 没有调度决策
- 没有中断处理
```

## 5. 多核情况

### 5.1 XiangShan 的多核支持

**XiangShan 支持多核，但 SPEC2006 只用单核**：

```makefile
# Makefile 中的核数配置
NUM_CORES ?= 1  # 默认单核
```

**多核用于**：
- 运行 Linux（需要多核调度）
- 运行多进程程序
- 测试缓存一致性

**SPEC2006 不使用多核**：
- 每个 benchmark 独立运行
- 不需要核间通信
- 不需要核间中断

### 5.2 多核 SPEC 评估

**如果要评估多核性能，需要使用 SPECrate**：

```
SPECrate 模式：
- 运行多个 SPEC2006 实例
- 每个实例在不同核上运行
- 测量整体吞吐量
- 需要操作系统支持

XiangShan 的 SPEC 评估：
- 单核模式
- 裸机运行
- 测量单核 IPC
```

## 6. 与嵌入式系统的对比

### 6.1 嵌入式系统的任务调度

**典型的嵌入式系统（如 FreeRTOS）**：

```c
// FreeRTOS 任务调度
void vTask1(void *pvParameters) {
    while (1) {
        // 任务 1 逻辑
        vTaskDelay(pdMS_TO_TICKS(100));  // 释放 CPU，等待调度
    }
}

void vTask2(void *pvParameters) {
    while (1) {
        // 任务 2 逻辑
        vTaskDelay(pdMS_TO_TICKS(200));  // 释放 CPU，等待调度
    }
}

int main() {
    xTaskCreate(vTask1, "Task1", 1000, NULL, 1, NULL);
    xTaskCreate(vTask2, "Task2", 1000, NULL, 2, NULL);
    vTaskStartScheduler();  // 启动调度器，需要定时器中断
    return 0;
}
```

**FreeRTOS 需要**：
- 定时器中断（SysTick）用于时间片轮转
- 上下文切换（保存/恢复寄存器）
- 调度算法（优先级调度）

### 6.2 SPEC2006 vs 嵌入式系统

| 方面 | SPEC2006 | FreeRTOS | Linux |
|------|----------|----------|-------|
| 线程数 | 1 | 多个 | 多个 |
| 调度器 | 无 | 优先级调度 | CFS |
| 定时器中断 | 不需要 | 需要（SysTick） | 需要 |
| 上下文切换 | 无 | 有 | 有 |
| 特权级 | M-mode | M-mode | M/S/U |
| 虚拟内存 | 无 | 无 | 有 |

## 7. 总结

### 7.1 核心结论

**SPEC CPU2006 的线程和调度需求取决于运行环境**：

| 运行环境 | 线程模型 | 需要调度 | 需要定时器中断 |
|----------|----------|----------|----------------|
| **裸机** | 单线程 | 不需要 | 不需要 |
| **Linux** | 多线程（11 个 benchmark） | 需要 | 需要 |

**XiangShan 的具体运行环境需要进一步确认**：
- 编译脚本在 NFS 上（`/nfs/home/share/ci-workloads/env-scripts/`），不在代码仓库中
- 需要查看实际的编译参数和运行方式

### 7.2 之前文档的错误

**错误 1**：声称"全部 29 个 benchmark 都是单线程"
- **事实**：SPECfp2006 有 11 个 benchmark 使用 OpenMP/pthreads

**错误 2**：声称"裸机运行，不需要 OS"
- **事实**：运行环境未确认，可能是 Linux

**错误 3**：声称"不需要定时器中断"
- **事实**：如果是 Linux 运行，多线程 benchmark 需要定时器中断做调度

### 7.3 正确的理解

**已确认的事实**：
1. SPECint2006（12 个）全部单线程
2. SPECfp2006（17 个）中 11 个使用 OpenMP/pthreads
3. XiangShan 能运行 Linux（`ready-to-run/linux.bin` 存在）
4. SPEC2006 的编译脚本在 NFS 上，不在代码仓库中

**未确认的信息**：
1. SPEC2006 在 XiangShan 上是裸机还是 Linux 运行
2. 多线程 benchmark 是否被编译为单线程模式
3. 定时器中断是否被使能

### 7.3 对嵌入式工程师的建议

**理解裸机程序和 OS 程序的区别**：

```
裸机程序（SPEC2006）：
- 单一执行流
- 无 OS 支持
- 直接操作硬件
- 程序自己控制生命周期

OS 程序（Linux 应用）：
- 多个执行流（进程/线程）
- OS 提供调度、内存管理、I/O
- 通过系统调用请求服务
- OS 控制程序生命周期
```

**SPEC2006 是裸机程序，不需要中断、不需要调度、不需要 OS。**
